# 阶段1-配置与启动模块-执行计划

## 1. 模块定位
配置与启动模块是 Topilot 的运行入口，负责初始化应用目录、生成和读取配置、诊断运行前状态，并最终启动 Telegram Bot。该模块直接决定项目是否能在目标主机上稳定起跑。

## 2. 模块核心功能
1. 构建 `~/.topilot/` 应用目录结构。
2. 提供首次运行交互式初始化。
3. 支持 `init`、`start`、`doctor` 等 CLI 命令。
4. 读取和校验 `config.json`。
5. 在配置覆盖时自动备份历史配置。

## 3. 输入与输出

### 3.1 输入
1. 用户在命令行输入的初始化参数。
2. `~/.topilot/config.json` 中的 JSON 配置。
3. 固定使用默认应用目录 `~/.topilot/`。

### 3.2 输出
1. 固定路径 `~/.topilot/config.json`。
2. `data/`、`logs/`、`workspace/` 等应用目录。
3. 标准输出中的诊断信息、错误信息和配置路径。

## 4. 核心实现逻辑
1. `paths.py` 使用 `build_app_paths()` 定义应用 home、数据、日志和工作区目录。
2. `config.py` 提供默认配置模板、JSON 读写、备份与字段校验。
3. `cli/main.py` 负责解析 CLI 参数并调度初始化、诊断和启动流程。
4. `load_settings()` 在启动前对关键配置项执行强校验，至少保证 `telegram.bot_token` 存在。
5. `logging_setup.py` 在启动阶段配置文件日志和控制台日志。
6. `doctor_report()` 在不启动 Telegram 和 Copilot 对话的前提下，检查配置文件、Token 状态、Copilot CLI 命令解析、命令可执行性、默认模型、超时配置和运行工作区状态。

## 5. 技术方案与选型说明

### 5.1 选用方案
采用“JSON 配置 + CLI 交互初始化”方案。

### 5.2 可选方案比较
1. 纯 `.env` 配置：简单，但层级结构表达弱，不利于扩展。
2. GUI 配置向导：体验更强，但超出当前项目复杂度。
3. JSON 配置：结构清晰、易扩展、便于备份和人工排查，最终选用。

## 6. 可自动化验收标准
1. 在默认应用目录首次执行 `topilot init --force`，完成交互后必须生成 `config.json`，且根节点包含 `telegram`、`copilot`、`runtime`、`storage`、`logging` 五个对象。
2. 当 `config.json` 已存在且内容发生变化时，再次写入必须生成 `config.backup-时间戳.json` 备份文件。
3. 执行 `topilot doctor` 时，输出中必须包含 `app_home=`、`config=`、`has_config=`、`config_status=`、`telegram_token=`、`copilot_cli_command=`、`copilot_cli_resolved_command=`、`copilot_cli_runnable=`、`copilot_model=`、`copilot_timeout_seconds=` 和 `issues=`。
4. 当 `config.json` 缺少 `telegram.bot_token` 时，执行 `topilot start` 必须返回非零状态，并输出“配置项 telegram.bot_token 为空”或同等明确错误。
5. 当配置存在空 Token、不可执行 Copilot 命令、无效超时或不存在的运行工作区时，`topilot doctor` 必须在 `issues=` 中输出对应问题，禁止静默通过。

## 7. 测试数据与测试方案

### 7.1 测试数据
1. 正常 JSON 配置样例。
2. 缺少 Token 的异常配置样例。
3. 覆盖写入前后的两份不同配置内容。
4. 不可执行 Copilot 命令、`timeout_seconds <= 0`、运行工作区不存在的异常配置样例。

### 7.2 测试方案
1. 使用隔离环境或临时路径夹具验证 CLI 行为，避免污染真实 `~/.topilot/`。
2. 通过文件存在性、JSON 字段校验和标准输出断言验证结果。
3. 对异常路径重点验证报错信息是否明确。

## 8. 模块依赖关系
1. 无业务前置模块依赖，是所有阶段开发的前提。
2. 为 Telegram 接入、日志、任务调度等模块提供运行配置。

## 9. 开发顺序
1. 先完成路径定义与目录创建。
2. 再完成默认配置模板和 JSON 读写。
3. 然后完成 CLI 命令入口。
4. 最后接入日志初始化和启动流程。

# 阶段2-会话管理与接管模块-执行计划

## 1. 模块定位
会话管理与接管模块负责维持“每个 Chat 一个当前上下文”的工作模式，并提供本地 Copilot 会话发现、接管、历史查看和运行中追踪能力，是项目差异化价值最高的模块之一。

## 2. 模块核心功能
1. 维护每个 Chat 的当前激活会话。
2. 支持手动新建、切换和删除会话。
3. 合并展示 Bot 已保存会话和本机新发现会话。
4. 扫描 `~/.copilot/session-state` 读取会话摘要。
5. 接管运行中会话，并在会话详情链路中持续刷新历史内容。

## 3. 输入与输出

### 3.1 输入
1. `chat_id`
2. 会话 ID 或会话 ID 前缀
3. `~/.copilot/session-state/` 目录中的 `workspace.yaml`、`events.jsonl`、`inuse.*.lock`

### 3.2 输出
1. `sessions.json` 中的会话列表、激活会话、当前模型
2. Telegram 会话列表、会话详情、历史摘要、追踪消息
3. 删除结果、接管结果、切换结果

## 4. 核心实现逻辑
1. `SessionStore` 负责保存 Bot 侧会话索引、当前激活会话和每个 Chat 的模型选择。
2. `CopilotSessionInspector` 负责扫描本机会话目录并提取工作区、模型、历史摘要和运行状态。
3. `TaskRunner.session_menu_items()` 负责把本地发现会话与 Bot 已保存会话合并去重后排序；同一会话同时存在于两侧时，展示字段优先采用本机实时扫描结果。
4. `session_use_text()` 对会话 ID 前缀做唯一性校验；匹配多个会话时返回歧义提示，不切换当前会话。
5. `takeover_session()` 在接管时回填会话元数据，并同步当前模型。
6. `_watch_session_live()` 负责对运行中会话进行轮询刷新，并在稳定结束后停止自动追踪。
7. Telegram 删除入口采用 `sdel:` 进入确认页、`sdelok:` 执行删除，避免误触按钮直接删除。
8. 会话菜单、详情、历史和删除确认页使用独立渲染函数构造按钮，保证回调入口、按钮文案和 callback_data 可被自动化测试验证。
9. 本地会话读取和删除只接受 `session-state` 根目录下的直接子目录名，拒绝绝对路径、`../` 等路径型会话 ID。

## 5. 技术方案与可选方案

### 5.1 选用方案
采用“Bot 侧会话索引 + 本地 session-state 扫描”的双源合并方案。

### 5.2 可选方案比较
1. 仅维护 Bot 自建会话：无法接管本机已有会话。
2. 完全依赖本地 session-state：不便于保存 Chat 维度的当前模型和会话归属。
3. 双源合并：既保留 Topilot 自身状态，又能接管外部会话，最终选用。

## 6. 可自动化验收标准
1. 对一个从未使用过的 `chat_id`，首次调用 `TaskRunner.submit()` 时必须自动创建默认会话，并将其写入 `sessions.json`。
2. `session_use` 对已有会话前缀必须能切换当前激活会话；对未保存但已发现的本机会话前缀必须触发接管逻辑；当前缀匹配多个会话时必须返回歧义提示，且不得切换当前激活会话。
3. `session_menu_items()` 返回结果必须满足：已保存会话与本机会话不重复、按 `last_event_at` 或最近使用时间逆序排序、当前激活会话被标记；当本机会话状态更新时，菜单中的标题、模型、来源和运行状态必须优先显示实时扫描结果。
4. 对运行中的本机会话，`session_live_payload()` 返回的 `signature` 变化时，Telegram 中对应追踪消息必须被刷新；当会话停止且连续 3 轮稳定后，自动追踪必须终止。
5. Telegram 删除流程必须先展示确认页；只有点击确认删除后，`delete_session(chat_id, session_id, delete_local=True)` 才能执行删除。
6. `delete_session(chat_id, session_id, delete_local=True)` 在 Bot 侧索引存在或本地会话目录存在的情况下，必须至少删除其中一项并返回“会话已删除”。
7. 会话菜单分页必须对负数、非数字和超出范围的页码做容错，最终展示页码必须夹到合法范围。
8. 会话详情、历史和删除确认页的按钮 callback_data 必须分别匹配 `suse:`、`shis:`、`sopen:`、`sdel:`、`sdelok:`、`smenu:` 等约定前缀。
9. 读取或删除本机会话时，绝对路径、`../` 和包含路径分隔符的 session_id 必须被拒绝，不能访问或删除 `session-state` 根目录外文件。

## 7. 测试数据与测试方案

### 7.1 测试数据
1. 空会话环境。
2. 含一个保存会话的 `sessions.json`。
3. 含多个 `session-state` 目录、带 `events.jsonl` 与 `workspace.yaml` 的本机会话样例。
4. 运行中和已结束两类会话样例。
5. 多页会话菜单、非法页码、详情页、历史页和删除确认页按钮样例。

### 7.2 测试方案
1. 使用临时目录构造 `sessions.json` 与伪造 `session-state` 文件结构。
2. 断言接管前后会话元数据变化。
3. 断言短前缀匹配多个会话时返回歧义提示，不修改当前激活会话。
4. 断言已保存会话与本机实时会话重复时优先展示本机元数据。
5. 断言历史摘要、运行状态和追踪终止条件。
6. 断言 Telegram 会话菜单分页、详情、历史和删除确认按钮结构。

## 8. 模块依赖关系
1. 依赖配置模块提供 JSON 存储路径和默认工作区。
2. 依赖 Telegram 接入模块提供菜单和回调入口。
3. 与模型发现与切换模块存在弱耦合，接管会话时需要同步模型信息。

## 9. 开发顺序
1. 先完成 `SessionStore` 的当前会话与会话列表维护。
2. 再完成 `CopilotSessionInspector` 的本地扫描。
3. 然后实现列表合并、详情展示和接管。
4. 最后实现运行中会话轮询追踪。
